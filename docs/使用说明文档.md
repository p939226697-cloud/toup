# 转盘抽奖系统 · 使用说明文档

> 微信扫码 → 大转盘抽奖 → 后台管理的一体化解决方案
> 适用场景：线下物料印刷二维码，消费者微信扫码参与抽奖

---

## 一、系统组成与访问地址

| 模块 | 地址 | 说明 |
| ---- | ---- | ---- |
| 用户端 H5 抽奖页 | `http://<服务器域名>/h5/?a=<活动ID>` | 消费者微信扫码直接打开 |
| PC 管理后台 | `http://<服务器域名>/admin` | 管理员账号密码登录 |
| 后端服务 | `server.js`（Node.js + Express + SQLite） | 端口默认 3000，可用环境变量 `PORT` 修改 |

**默认管理员账号：`admin` / `admin123`**（首次登录后请立即在左下角「修改密码」中修改）

## 二、启动与部署

### 本地启动
```bash
cd lottery-system
npm install          # 首次安装依赖
node server.js       # 启动服务（默认 3000 端口）
```
启动后自动完成：
- 创建 SQLite 数据库 `data/lottery.db`
- 创建默认管理员账号
- 创建一个已发布的演示活动（ID=1，默认 9 个奖项与概率）

### 生产部署要点
1. **域名与 HTTPS**：微信内置浏览器要求 HTTPS 访问，请将服务部署到有域名和 SSL 证书的服务器（Nginx 反向代理到 3000 端口即可）。
2. **二维码链接**：后台生成的访问链接基于当前访问域名自动拼接，请务必通过正式域名打开后台再生成/下载二维码用于印刷。
3. **数据备份**：所有业务数据存于 `data/lottery.db` 单文件，定期备份该文件即可。
4. **微信内打开**：H5 页面本身即微信 H5，扫码可直接打开；若需获取用户真实微信昵称（自动授权），需接入微信公众号网页授权（见第五节说明）。

## 三、后台操作说明

### 3.1 登录
浏览器打开 `/admin`，输入管理员账号密码登录。未登录无法访问任何后台数据接口。

### 3.2 活动编辑与发布

**新建活动**：活动管理页右上角「＋ 新建活动」，系统自动按默认概率初始化 9 个奖项（100/50/20/10/5/2/1/0.5 元 + 谢谢惠顾）。

**编辑内容**：
- **页面文案**：活动标题、活动说明、活动规则文字；
- **图片素材**：活动头图、转盘底图、抽奖按钮图、弹窗背景图（点击虚线框上传，≤3MB，未上传使用系统默认样式）；
- **奖品管理**：可新增/删除奖项，修改每个奖项的名称、金额、概率（分子/分母，如 `1/100` 即每人 1% 概率）。至少保留一个「谢谢惠顾」奖项，系统会自动兜底追加。

**重要规则：所有修改必须点「🚀 发布活动」才对用户生效，「保存草稿」仅暂存、不影响线上页面。** 列表中会显示「有未发布草稿」标记。

### 3.3 生成二维码与链接

点击「发布」或「二维码」按钮，弹窗展示：
- **访问链接**：一键复制；
- **二维码图片**：600×600 高清 PNG，点击「下载二维码图片」保存，可直接用于线下印刷。

### 3.4 复制副本 / 停用活动

- **复制副本**：一键复制现有活动的全部配置（文案、素材、奖品、概率），生成一份草稿状态的新活动，适合快速开新一期抽奖；
- **停用活动**：停用后用户扫码会看到「活动已结束」提示，后台数据仍完整保留，可再次编辑后重新发布。

### 3.5 数据明细（模块B-1）

支持按以下条件筛选：**活动、时间范围、手机号、是否完成抽奖、是否中奖**。
列表字段：扫码时间（精确到秒）、微信昵称、手机号、是否完成抽奖、抽奖结果（中奖金额/谢谢惠顾）、是否重复参与、访问来源（微信内置浏览器等）。

**导出 Excel**：点击「⬇ 导出Excel」按当前筛选条件导出全部明细，包含两个工作表：
- 「参与明细」：全量成功参与记录；
- 「重复尝试记录」：被拦截的重复提交（防刷记录），原始业务数据不可删除。

### 3.6 汇总统计看板（模块B-2）

支持按活动 + 时间段筛选，展示：
- **全局指标卡**：累计扫码人数、累计完成抽奖、累计中奖人数、累计发放奖金、重复提交尝试次数；
- **每日统计表**：日期、当日扫码人数、当日完成抽奖人数、当日中奖人数、当日中奖总金额；
- **各档位奖品中出情况**：每个奖品中出份数与合计金额；
- **导出 Excel**：三个工作表（每日统计 / 奖品档位汇总 / 全局汇总）。

## 四、用户端流程说明（消费者视角）

1. **扫码**：微信扫描印刷物料上的二维码，直接打开活动页（微信内置浏览器，无需下载 APP）；
2. **昵称授权**：弹窗申请获取微信昵称（仅公开昵称）；拒绝则无法进入下一步；
3. **手机号确认**：回填昵称 → 输入 11 位大陆手机号（实时格式校验）→ 阅读规则提示（一机一号限抽 1 次）→ 点击「确认进入抽奖」；
   - 已参与过的手机号会提示「该手机号已参与本次抽奖，不可重复参与」并拦截；
4. **大转盘抽奖**：点击中央「点击抽奖」按钮，转盘旋转约 5 秒减速停在结果扇区；
5. **结果弹窗**：展示中奖金额（红色大字）或「谢谢惠顾」。

页面底部展示隐私合规提示（告知昵称与手机号的收集用途）。

## 五、防作弊与安全设计

1. **中奖算法完全在服务端执行**：使用 Node.js `crypto.randomInt` 安全随机数，逐档位按独立概率判定；前端仅接收结果做动画，**前端 JS 无法控制中奖结果**；
2. **手机号唯一限制**：同一活动内一个手机号仅可参与 1 次抽奖，重复提交被拦截并记录（计入重复参与统计）；
3. **抽奖幂等**：同一参与记录重复请求抽奖接口，只会返回首次结果，不会重复中奖；
4. **后台访问控制**：所有管理接口需登录 Token 鉴权；参与明细原始数据不提供删除接口；
5. **概率配置在服务端**：H5 页面接口只下发奖品名称（用于画转盘），不下发概率，杜绝前端篡改。

> **微信昵称授权说明**：演示环境中昵称由用户确认填写。若已拥有微信公众号（服务号），可在 `public/h5/index.html` 中接入微信网页授权（`snsapi_userinfo`），实现真实的静默昵称获取，业务流程其余部分无需改动。

## 六、常见问题

| 问题 | 处理方式 |
| ---- | ---- |
| 忘记管理员密码 | 删除 `data/lottery.db` 中 admins 表对应记录后重启，或联系技术人员重置（会重新初始化默认账号） |
| 修改概率后未生效 | 概率修改保存的是草稿，需点击「发布活动」立即生效 |
| 扫码提示活动已结束 | 活动被停用，后台重新编辑并发布即可恢复 |
| 数据如何备份 | 备份 `data/lottery.db` 文件（建议每日定时备份） |
| 换服务器/域名 | 迁移整个项目目录 + 数据库文件，通过新域名访问后台重新生成二维码 |
